# 📝 my_articles

Репозиторий теперь подготовлен под **GitHub Pages** как персональный сайт: главная страница, блог со статьями, страница проектов и публичные карточки обновлений.

## Структура

```text
my_articles/
├── _config.yml                    # конфигурация GitHub Pages / Jekyll
├── _articles/                     # публичные статьи
│   └── diploma_supplement_service/
├── _data/
│   └── projects.yml               # описание проектов для витрины
├── _includes/                     # общие шаблоны
├── _layouts/                      # макеты страниц
├── assets/
│   ├── css/main.css               # стили сайта
│   └── diploma_supplement_service/
├── index.html                     # главная
├── blog.html                      # список статей
├── projects.html                  # список проектов
└── about.md                       # страница "Обо мне"
```

## Что уже сделано

- статьи перенесены в коллекцию `_articles/`, совместимую с GitHub Pages;
- добавлены шаблоны сайта и навигация;
- создана витрина проектов и лента последних обновлений;
- сохранён текущий контент на русском и английском;
- настроены человекочитаемые URL для статей вида `/blog/<project>/<slug>/`.

## Как публиковать новые статьи

1. Добавьте Markdown-файл в `_articles/<проект>/`.
2. Используйте имя файла в формате `ГГГГ-ММ-ДД-slug.md`.
3. Добавьте фронтматтер:

```yaml
---
title: "Заголовок статьи"
project: diploma_supplement_service
date: 2026-06-03
lang: ru
summary: "Короткое описание для карточки статьи."
tags: [python, docker]
links:
  repo: "https://github.com/..."
  demo: "https://example.com"
---
```

4. Для английского перевода храните файл рядом с оригиналом и указывайте:

```yaml
lang: en
translation_of: 2026-06-03-slug.md
```

## Как обновлять проекты

- описание проектов хранится в `_data/projects.yml`;
- там же задаются `repo`, `demo`, стек и краткое описание;
- страница `/projects/` автоматически подхватывает последние статьи по каждому проекту.

## Настройка GitHub Pages

- проверьте `url` и `baseurl` в `_config.yml`;
- если сайт будет жить в репозитории `username.github.io`, установите `baseurl: ""`;
- если сайт будет жить в проектном репозитории, оставьте `baseurl` равным имени репозитория.

## Локальная проверка

Если у вас настроен Jekyll:

```sh
bundle exec jekyll serve
```

Если Jekyll локально не установлен, этот репозиторий всё равно можно публиковать напрямую через GitHub Pages.
